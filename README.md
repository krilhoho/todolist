# To-Do List

Небольшой сервис на FastAPI для ведения списка личных или учебных задач. Позволяет создавать задачи, просматривать их и отмечать выполненные.

## Установка

Нужны Git и Python 3.12. На этой версии Python проект проверяется в GitHub Actions.

Команды ниже предназначены для macOS и Linux.

```bash
git clone https://github.com/krilhoho/todolist.git
cd todolist
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

## Запуск

Обычный запуск:

```bash
python -m uvicorn app_final:app
```

После запуска доступны:

- [Интерактивная документация](http://127.0.0.1:8000/docs).
- [Проверка работоспособности](http://127.0.0.1:8000/health).
- [Версия приложения](http://127.0.0.1:8000/version).

Для разработки можно использовать автоматический перезапуск при изменении кода:

```bash
python -m uvicorn app_final:app --reload
```

Для остановки сервера нажмите `Control+C` в его терминале.

## Маршруты

| Метод | Адрес | Назначение |
|---|---|---|
| GET | `/health` | Проверить работоспособность |
| GET | `/version` | Получить версию приложения |
| POST | `/tasks` | Создать задачу |
| GET | `/tasks` | Получить список задач |
| GET | `/tasks/{task_id}` | Получить задачу по номеру |
| PATCH | `/tasks/{task_id}/complete` | Отметить задачу выполненной |

При создании задачи передайте JSON:

```json
{
  "title": "Подготовить отчёт"
}
```

Название должно содержать от 1 до 200 символов. Приложение самостоятельно назначает номер и устанавливает `done: false`.

Создание возвращает код `201`. Для несуществующей задачи возвращается `404`, для некорректных входных данных — `422`.

## Настройки окружения

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `APP_NAME` | `To-Do List` | Название в документации и логах |
| `APP_VERSION` | `0.1.0` | Версия в документации и `/version` |

Пример запуска с другими настройками:

```bash
APP_NAME="My To-Do List" APP_VERSION="0.2.0" python -m uvicorn app_final:app
```

Настройки считываются при запуске приложения. Для их изменения перезапустите сервер с новыми значениями.

Файл `.env.example` содержит образец настроек. Приложение читает переменные окружения процесса; файл `.env` автоматически не загружается.

## Проверка работоспособности

При работающем сервере выполните в другом терминале:

```bash
curl http://127.0.0.1:8000/health
curl http://127.0.0.1:8000/version
```

Для настроек по умолчанию ожидаются ответы:

```json
{"status":"ok"}
```

```json
{"version":"0.1.0"}
```

## Автоматические тесты

Из корня проекта, с активированным виртуальным окружением, выполните:

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -v
```

В проекте восемь тестов. Они проверяют работоспособность, создание и получение задач, сохранение отметки выполнения и обработку ошибок.

Каждый тест получает пустое хранилище. Тестовый клиент самостоятельно запускает приложение внутри процесса проверки.

## Логи и диагностика

Логи выводятся в терминал, где запущен сервер. Записываются запуск и остановка приложения, создание и завершение задач. Uvicorn также выводит сведения о запросах.

Примеры сообщений приложения:

```text
Starting To-Do List, version 0.1.0
Task created: id=1
Task completed: id=1
Stopping To-Do List
```

| Проблема | Что проверить |
|---|---|
| `ModuleNotFoundError` | Активируйте `.venv` и установите зависимости |
| `Address already in use` | Проверьте, не запущен ли уже сервер в другом терминале; остановите прежний экземпляр через `Control+C` |
| `/health` не открывается | Проверьте, работает ли сервер и нет ли ошибок в его терминале |
| Ошибка `404` при обращении к задаче | Проверьте номер через `GET /tasks`; после перезапуска задачи очищаются |
| Ошибка `422` | Проверьте JSON, длину названия и целочисленный номер задачи |

## Хранение данных

Задачи хранятся в памяти одного процесса. При остановке или перезапуске приложения данные очищаются. Это относится и к автоматическому перезапуску с `--reload`.

## GitHub Actions

Workflow находится в `.github/workflows/ci.yml` и запускается при `push` и `pull_request`.

Он устанавливает зависимости и выполняет:

```bash
python -m pytest -v
```

После успешного прохождения тестов создаётся artifact `todolist-files` с файлами проекта. Результаты и архив доступны на вкладке Actions в репозитории.
